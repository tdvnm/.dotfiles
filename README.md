# dotfiles

The small set of configs needed to restore my NixOS/Sway setup as `toad`.
No Home Manager, symlink manager, Emacs package cache, or clipboard database.

| Folder | Owns |
| --- | --- |
| `nixos/` | Pinned system packages, hardware, users and services; `configuration.nix` is the index |
| `sway/`, `waybar/` | Desktop, shortcuts, bar, terminal/lock helpers |
| `rofi/`, `dunst/`, `kitty/`, `fish/` | Launcher tools, notifications, terminal and shell |
| `doom/` | Current personal Emacs config, including its own guide |
| `copyq/` | Clipboard app settings, commands and theme, **not clipboard contents** |
| `nvim/` | Existing Neovim config |
| `monaspace_neon/` | The local font files the desktop actually uses |
| `wallpapers/wxp.png` | Current desktop and lock-screen background |
| `org/` | Starter agenda and two log templates; never replaces existing Org files |

Other wallpapers already in the repo remain available; restore installs only
`wxp.png`. The repository lives at `~/.config/.dotfiles`, as Sway expects.

## Restore after reinstalling

Start with a working NixOS install and the `toad` account/password. Keep a copy
of this repository **off this disk** before reinstalling; uncommitted changes
will not appear when you clone the remote. Run the user-config commands as
`toad`, not root. Close apps while copying their settings.

### 1. Restore NixOS

The repo is pinned to nixpkgs `b6018f87da91d19d0ab4cf979885689b469cdd41`
(NixOS 25.11). Keep `flake.lock`; do not update it during restoration.

After restoring/cloning this repository into `~/.config/.dotfiles`:

```sh
cd ~/.config/.dotfiles
# Keep the hardware file generated by the NEW installation.
cp /etc/nixos/hardware-configuration.nix /tmp/new-hardware-configuration.nix
sudo cp -a nixos/. /etc/nixos/
sudo cp /tmp/new-hardware-configuration.nix /etc/nixos/hardware-configuration.nix
```

Before rebuilding, review these two files in `/etc/nixos/modules/`:

- `boot.nix`: the saved LUKS mapper and `resume_offset` belong to the old disk
  layout. Remove the `boot.resumeDevice` setting and `resume_offset=...` kernel
  parameter for the first rebuild after reformatting. Configure hibernation
  again only after the new `/swapfile` exists and its device/offset are known.
- `hardware.nix`: update the `/mnt/data` UUID, or remove that mount when the
  extra filesystem is absent. Until hibernation is configured again, use
  `criticalPowerAction = "PowerOff"` instead of `"Hibernate"`.

Even the same laptop gets new UUIDs/offsets when its filesystems are recreated.
For a different laptop, also review the Intel kernel parameters and Sway's
`eDP-1`/`HDMI-A-1` display names. For a different username, change
`users.users.toad` in `nixos/configuration.nix`.

```sh
sudo nixos-rebuild build --flake /etc/nixos#nixos
sudo nixos-rebuild switch --flake /etc/nixos#nixos
```

The system config installs the desktop apps and development tools. It now also
declares `emacsPackages.pdf-tools` (the PDF helper previously installed only in
the user profile) and Unifont (Emacs's symbol font). Fingerprints and passwords
must be enrolled/set again.

### 2. Restore app configs

```sh
cd ~/.config/.dotfiles
bash restore.sh           # preview only
bash restore.sh --apply   # copy configs, backing up replaced files
fc-cache -f
```

The script copies regular config files and preserves executable script modes.
Replaced files go under `~/.local/state/dotfiles-backup/`. Existing personal Org
files and CopyQ history are left alone. It does not delete unrelated destination
files, rebuild NixOS, install Flatpaks, or start/restart apps.

### 3. Install Doom itself

`doom/` is the personal config; Doom's source is a separate checkout. These are
the clean source revisions used when this snapshot was taken on 2026-09-14:

```sh
git clone https://github.com/doomemacs/doomemacs ~/.config/emacs
git -C ~/.config/emacs checkout 4113a6f05ece821a505c548c2e98645604ac4e9f
git -C ~/.config/emacs submodule update --init --recursive
git -C ~/.config/emacs/sources/doom+ checkout b9391c34dbb26df79d804444def3371c1ca8c342
~/.config/emacs/bin/doom install
~/.config/emacs/bin/doom sync
```

Use a fresh destination for the clone; don't overwrite an existing Emacs
checkout. Doom fetches its packages from the network. Its three extra personal
packages are not pinned in `doom/packages.el`, so their future downloads may
differ; the config and Doom source revisions are preserved, not a complete
offline package archive. Log out and back in to start the restored Sway session.

### 4. Optional Flatpak apps

These apps were installed outside the Nix package list. To restore them too:

```sh
sudo flatpak remote-add --if-not-exists flathub https://flathub.org/repo/flathub.flatpakrepo
sudo flatpak install flathub app.zen_browser.zen com.bitwarden.desktop \
  com.discordapp.Discord com.google.Chrome com.rtosta.zapzap com.spotify.Client \
  com.stremio.Stremio com.visualstudio.code de.wwwtech.gitte \
  io.github.ungoogled_software.ungoogled_chromium org.gnome.baobab \
  org.quetoo.Quetoo org.signal.Signal
```

Flatpak versions and app logins are not captured. Locally built Aseprite and
separately installed agent CLIs are not needed to start this desktop and must
be installed separately if wanted.

## What needs a separate private backup

Actual `~/org`, `~/krea`, projects, photos and game saves; browser profiles;
SSH/GPG keys; app credentials; NetworkManager connections; and any Docker,
database or Tor onion-service data. Those are personal data, not dotfiles.
The templates here recreate the Org structure, not your notes or task history.
CopyQ uses its internal editor without extra dependencies; its optional external
editor setting currently names `gedit`, which is not installed by this setup.

## Keeping this current

These are copies, not live links. After changing an app, copy its config back
here before committing. Keep NixOS edits in the existing topic modules. For
CopyQ, copy only `copyq.conf`, `copyq-commands.ini` and `themes/sakura.ini`.
Never copy its whole state directory. For Doom, exclude `.git/`, `custom.el`,
compiled files and editor backups.

The restore script is tested against a temporary home (`--home DIR`), including
preview, backups, repeat runs and preserving existing Org data. The modular
NixOS configuration reproduced the installed system derivation before the two
explicit restore dependencies were added. This is a reproducible config setup,
and the final configuration also evaluates successfully. A bare-metal reinstall
and offline restoration have not been tested.
